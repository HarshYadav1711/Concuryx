# Design Direction

## Philosophy

Concuryx should look like a serious engineering tool: information-first, precise, restrained, and dense only where useful. Typography, spacing, semantic hierarchy, and evidence take priority over decoration. Motion is permitted only when it explains state or time.

The interface must be responsive, keyboard accessible, reduced-motion friendly, and designed with WCAG-conscious contrast.

## Approved baseline palette

| Token | Value |
|---|---|
| Background | `#0E1116` |
| Surface | `#151A21` |
| Raised surface | `#1B222C` |
| Primary text | `#F3F1EA` |
| Secondary text | `#9CA6B3` |
| Primary accent | `#63D0C6` |
| Attention | `#E5A65B` |
| Error | `#E06C75` |

These values must not be arbitrarily replaced.

## Avoid

- Fake hacker styling, cyberpunk neon, Matrix backgrounds, and decorative fake terminals.
- Excessive gradients, glassmorphism, rounded pills, or meaningless cards.
- Decorative graphs, fake data, excessive animation, or generic AI-dashboard styling.

## Information priorities

Later designs should prioritize run configuration, template/target identity, preparation progress, request-wave state, per-request outcomes, timing, aggregation, and authorization evidence. No screen or component design is approved in Phase 0.
